## 📐 비즈니스 도메인 구조 요약

```
자산 상태: AVAILABLE → ASSIGNED → RENTED → RENTED_RETURNED → AVAILABLE(or SOLD)
                                   ↑↓ REPAIRING (AVAILABLE 복귀 미자동)

계약 상태: ACTIVE → EXTENDED | SHORTENED | SUCCEEDED | COMPLETED

배차 유형: OUTBOUND / INBOUND / EXCHANGE / MOVEMENT / RETURN
배차 상태: REQUESTED → PENDING → DISPATCHED → DELIVERED → COMPLETED / CANCELLED

청구 상태: REQUESTED → UNPAID → PARTIAL → PAID / REJECTED
```

### WTT-003 | 대차(EXCHANGE) 교체 전체 체인
**Actor**: 영업팀 → 출고담당 → 정비팀  
**경로**: EXCHANGE 의뢰 → 신규 ContractAsset 생성 → 배정 → 출고검수 → 구자산 회수

| 검증 항목 | 결과 |

**ERR-001**: `handleExchangeSubmit` (Contracts.tsx:400)에서 기존 ContractAsset의 `status: 'RETURNED'`, `actualReturnDate` 업데이트 코드 없음. 기존 자산이 계약에 여전히 연결된 채로 남음.

**GAP-003**: 교체 당일 구자산과 신자산 모두 청구 가능 상태 — `generateBillingsForMonth`에서 교체일 기준 일할 분리 로직 없음.

**ERR-003**: 동일 계약에 처리되지 않은 EXCHANGE가 있어도 추가 EXCHANGE 의뢰를 막는 중복 방지 없음.
